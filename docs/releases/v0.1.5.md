# emachine v0.1.5

The AppImage stores browser databases, caches, logs, crash reports, and downloaded interfaces in `~/.cache/emachine/` instead of `~/.config/emachine/`.
An absolute `XDG_CACHE_HOME` selects a different cache base directory. Empty or relative values use the default.

On first launch, the client moves known desktop files from the old profile while holding its single-instance lock.
Saved connections, project selection, browser databases, cookies, and downloaded interfaces remain available.
Server configuration and unknown files stay in the configuration directory.
Migration stops when files conflict or the cache is unavailable. It never silently overwrites a database or falls back to configuration storage.

An explicit `--user-data-dir` keeps desktop storage in the selected profile. Development runs keep their existing paths.
Clearing the entire desktop cache removes saved client settings and interfaces. Server projects, terminals, and jobs remain independent.

Replace the AppImage and relaunch the client to apply this change. The **Refresh** control cannot change native storage paths.

Release preparation tests the exact AppImage for storage migration, startup and restart persistence, interface refresh, and recovery.
Release assets remain the Linux x86-64 AppImage, checksums, release metadata, and `latest-linux.yml` for external tooling.
